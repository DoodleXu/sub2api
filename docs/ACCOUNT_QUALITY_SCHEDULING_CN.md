# 全平台健康优先调度与欠费保护

状态：准备发布 v0.2.37。开发基线为 `239d9af84`（v0.2.36），候选版本须通过精确提交的 CI 与 Security Scan 后才能创建发布标签。原聊天只读盘点的线上版本为 v0.1.265；GitHub/GHCR 发版与生产部署分别验收。

## 生效规则

`account_quality_scheduling_enabled` 默认开启。保留权限、分组、利润门、模型能力、归档/影子账号、配额、并发及不可迁移的服务端上下文检查，再对合格候选排序：

1. 可靠性优先。有效结果达到20条后，错误率不高于5%为健康，超过5%至20%为降级，超过20%为较差；样本不足为未知。
2. 同等级比较速度，统计维度包含实际模型、接口能力、传输方式、流式状态及请求推理等级。优先15分钟，样本不足回看24小时；每桶最多200条。流式使用首个有效输出耗时，非流式使用完成耗时。延迟样本不足10条时不据此建立速度优势。
3. 最快候选20%范围内依次比较负载、时效有效的上游倍率、普通会话粘性和静态优先级。满载账号不阻止尝试其他合格候选。
4. 已知健康候选存在时，每20个请求最多一个请求获得未知/恢复账号的探索机会。同一请求多次选号沿用同一个探索决定。没有健康候选时仍允许未知账号参与。Redis探测租约保证单个桶一次只放行一个探测，长请求定期续租。
5. 60秒内连续3次瞬时故障，或15分钟至少20条有效结果且瞬时故障达到50%，熔断60秒，重复失败指数递增至最多5分钟。恢复阶段一次一个探测，连续两次成功解除；旧在途成功不能解除新一轮熔断。

明确账号级的鉴权、连接故障还写入账号整体桶，影响其他模型；单模型429、请求参数、内容策略及客户端取消不进入账号整体处罚。HTTP桥接的WS与原生WS分桶，逐turn观察，桥接内部HTTP共享观察器，不重复计数。现有OpenAI专属健康熔断配置保留兼容读取，新请求统一使用共享健康熔断。

Redis读取使用短时本地缓存和批查，不扫描历史用量或错误表。跨实例统计采用CAS去重，探测及出站欠费阻断使用原子检查。共享许可/阻断不可读取时不放行新的探测或出站请求；统计写入失败会记录告警并保留本地统计。

## 一次请求的失败边界

失败账号排除集只增不减，跨模型映射及分组回退保留。候选耗尽立即结束，不再清空排除集等待重选。保留原有换号次数、请求取消、语义输出及异步任务安全边界。

普通上游故障不在同账号重放。明确未执行推理的协议修正和凭据刷新仍沿用适配器的受限修复路径；请求内成功刷新须回读数据库核对完整凭据及代际，仅授权当前请求使用新快照，包含 WS 首轮取 token 与影子凭据，健康结果归入实际使用的代际。管理员替换凭据、手动恢复或后续欠费暂停不能被该授权绕过。Antigravity原有显式启用的免费额度转付费积分使用一次专用许可，不放开普通429重试。已经提交的媒体任务仍由原账号查询/取消，不把查询计入生成耗时。

## 明确欠费

仅识别真实上游错误字段中明确的账号余额不足文案或结构化计费错误。普通403/429、`quota exceeded`、窗口限额、模型钱包和请求回显不能触发欠费停调。HTTP及WS均在自定义错误策略、池模式、协议回退和客户端输出之前检查，包括 V158 自动透传入口。原生 WS 与 HTTP 桥在第二轮及后续轮次出站前被拒绝时，保留当前轮重放封装，安全重建输入和工具上下文；无法重建时关闭连接，禁止重放首包。

命中后立即阻断该账号代际，数据库原子写入 `schedulable=false`、`extra.scheduler_balance_pause`，保留原备注并追加一次中文记录。摘要采用固定计费错误说明，避免上游文案夹带密钥或请求内容；备注包括时间及追踪标识。同一暂停期间并发报错不会重复追加备注。持久化失败保留本地/Redis阻断，有限次数重试并告警。

影子账号的明确欠费按请求开始时的母账号凭据快照停调母账号，出站时也检查母账号欠费阻断；母账号普通手动停调仍不影响影子账号独立调度。

只有管理员的“开启调度”或显式批量开启操作能清除本次暂停。普通编辑、成功测试、余额/额度探测及后台刷新不能解除。`scheduler_generation` 由数据库维护；管理员恢复或凭据更新后，旧在途请求不能覆盖新代际。HTTP公共传输在真正出站之前再次检查数据库和共享欠费阻断。

## 迁移与兼容

迁移：`backend/migrations/249_account_scheduling_safety.sql`。

- 只删除存量 `extra.openai_continue_scheduling_after_limit`，不删除其他配置和数据库列。
- 数据库触发器守住调度代际与欠费暂停所有权，防止旧ORM对象、旧版本后台任务覆盖新状态。
- 创建、编辑、批量写入及数据库插入剥离超频键；旧客户端提交该键时，其余合法字段仍可保存。服务端所有权字段也不接受客户端伪造。
- 移除超频开关、状态、专属排序层、限额绕过及专用错误隐藏。普通429、窗口和模型限额恢复原有正常处理。
- 推理请求/响应格式保持兼容。管理接口只新增可选 `quality_scheduling` 和策略开关；旧客户端省略开关时保留原值。
- 后台显示生效策略、样本量、统计窗口、更新时间、各模型错误率及延迟。未知值不会显示为零错误。旧同账号重试配置仅保留兼容数据，界面明确停用。

## 发布与回滚门槛

本次没有执行生产部署。上线前仍须在隔离演练环境完成 v0.1.265 到本基线的完整迁移及回滚演练，不能用本地最新基线迁移测试代替跨版本演练。

1. 备份数据库、配置、镜像/二进制及迁移版本；在生产数据的脱敏副本上执行全部缺失迁移，核对账号数量、归档/影子归属及其他配置未改变。
2. 先在演练环境注入余额不足403、模型429、普通403/5xx、断连、部分流输出和任务已提交场景。并发运行多实例，验证旧请求晚到、快照滞后、Redis/数据库异常与管理员恢复。
3. 演练降级到旧二进制。保留迁移249的欠费保护触发器；旧二进制不能依靠普通更新恢复欠费暂停，需使用新版管理员入口或经过审核的显式恢复操作。旧二进制本身不具备新的失败排除/健康调度实现，不能声称二进制回滚仍保留全部新调度行为。
4. 小流量开启，比较最终成功率、每请求上游尝试数、首字P50/P95、调度开销和探测占比。逐请求核对Ops上游尝试列表，区分失败尝试与用户最终失败。
5. 验收必须满足：停调生效后新请求命中欠费账号为0；同一轮再次故障尝试已失败账号为0；明确模型限流造成欠费误停为0。

仅回滚排序时，通过管理设置关闭 `account_quality_scheduling_enabled`。该操作保留欠费保护、正常限额、失败账号排除及共享熔断，不恢复超频。不要通过删除暂停标记或重新加入旧超频键来回滚。
