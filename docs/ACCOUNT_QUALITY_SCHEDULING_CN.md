# 官方调度与独立欠费保护

当前实现日期：2026-10-24。开发基线为 fork v0.2.38 / `ba248cced`，本轮在 `codex/fork-convergence` 完成开发，并按授权审核、提交后合入 fork 的 `main`。已于2026-10-24发布 v0.2.39（提交 `828a7ef49`），尚未部署生产服务器。此前 v0.2.37 的“全平台健康优先”实现已在本轮收敛；历史发行不代表当前改动已经上线。

## 当前选择与恢复规则

选号使用官方主流程：账号资格、分组/模型能力、配额、并发、归档/影子约束和利润门之后，使用原有优先级、负载、粘性/逃逸、Top-K/高级权重及订阅优先配置。OpenAI 原有 EWMA 与健康熔断恢复正常调用。

退出请求路径的机制：每次选号汇总最多200条历史样本、跨维度质量排序、Redis质量历史/CAS、全平台共享探测租约、未知账号单并发限制、覆盖原有权重的健康排序。没有新增一套替代排序或插件框架。新账号、新模型及 OAuth 凭据更新不再因为“样本不足”被限制成一个在途请求。

只有适配器确认可以安全重放且尚未产生有效输出的暂态错误，才允许同账号重试。公共恢复使用账号次数与错误级上限，检查请求取消、重试截止时间和 Retry-After；单次等待超过8秒时换号，不提前重试。拒绝明确欠费、鉴权/凭据失败及不可重放的状态。已产生语义输出和已提交媒体任务沿用原有不可重放边界。

耗尽、明确硬失败和利润否决的账号在同一逻辑请求内保持排除，不通过清空排除集反复选号。WS 沿用当前轮安全重建上下文，成功结束一轮后才能重置下一轮预算，禁止回退重放首包。Gemini 原有服务内有界恢复保留；Vertex 共享容量429不再误冷却账号。Antigravity 模型容量503使用公共最多3次预算，未恢复原有嵌套60次容量循环。

## 独立保留的财务与凭据安全边界

- 明确余额不足仍优先于池模式和自定义错误码处理，原子写入 `schedulable=false` 和 `scheduler_balance_pause`，保留备注并只追加一次停调说明。
- 迁移249继续维护调度代际和暂停所有权。普通编辑、测试、探测和后台刷新不能恢复欠费暂停；只有明确管理员恢复操作可以清除。
- 旧在途请求不能覆盖管理员恢复或凭据更换后的新代际。请求内成功 OAuth 刷新仍须确认实际落库的凭据，仅授权当前请求使用新快照。
- 影子账号的明确欠费仍归属实际凭据母账号；母账号普通手动暂停不改变影子的独立调度规则。
- `GetAccountDispatchState` 使用单条账号投影查询，只载入安全判断需要的状态/凭据字段，不加载分组、代理等关联。适配器入口和真正出站前各保留一次权威检查，避免检查间管理员操作造成竞态。影子账号还需检查母账号。
- Redis 仅保留明确财务阻断的代际键；统计故障不再通过质量探测许可阻断请求。财务安全状态本身无法确认时仍不放行，不以性能优化为由撤掉该边界。
- Antigravity 免费额度转付费积分继续采用独立单次许可，不能因恢复普通暂态重试而无限切换或绕过欠费保护。

现有 `BeginAccountQualityAttempt` 等内部适配器接口保留名称以降低本次改动面，但实现只负责财务/凭据安全和错误归属，不再执行质量历史读写或探测。
